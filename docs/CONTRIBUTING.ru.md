## Начало работы

```bash
git clone https://github.com/Ping4Win/ping4win-utils.git
cd ping4win-utils
./build.sh                         # сборка и создание бандла
./build/Ping4WinUtils --selftest   # быстрая проверка (SELFTEST OK)
./build.sh --install               # установка в /Applications и запуск
```

**Требования**: macOS 14+, Apple Silicon, Xcode Command Line Tools.  
Сборка — это обычный вызов `swiftc` (см. `build.sh`), без Xcode-проекта, без внешних зависимостей, воспроизводима по замыслу. `Package.swift` существует для того, чтобы редакторы с поддержкой SwiftPM могли индексировать код.

### Стабильная подпись (опционально)

По умолчанию `build.sh` подписывает ad-hoc — хеш кода меняется при каждой сборке, и macOS будет повторно запрашивать разрешения Accessibility/Screen Recording. Выполните

```bash
./Tools/setup-signing.sh
```

один раз, чтобы создать бесплатный самоподписанный идентификатор (`Ping4Win Utils Signing`) в отдельном keychain. Тогда `build.sh` будет подписывать локальные сборки им, и выданные разрешения сохранятся между пересборками. Этот идентификатор — исключительно локальное удобство.

Официальные релизы подписываются **Developer ID** от Apple, нотаризируются и прикрепляются автоматически через CI — загруженные приложения открываются без предупреждений Gatekeeper.

## Структура проекта

| Папка | Назначение |
|---|---|
| `Sources/Ping4WinUtils/App` | Жизненный цикл приложения и элемент строки меню |
| `Sources/Ping4WinUtils/Core` | Локализация, разрешения, ключи UserDefaults |
| `Sources/Ping4WinUtils/Services` | Вся логика: энергия, монитор, прокрутка, switcher |
| `Sources/Ping4WinUtils/UI` | Только SwiftUI-представления — без бизнес-логики |
| `Sources/Ping4WinUtils/Support` | Диагностика `--selftest` и `--sensors` |
| `Tools` | Генератор иконок и упаковка DMG |

**Конвенции:**

- **UI наблюдает за сервисами; сервисы никогда не импортируют SwiftUI.** Сохраняйте эту границу.
- Синглтоны доступны как `Type.shared` и публикуют состояние через Combine (`ObservableObject` — без макросов Observation).
- Комментарии объясняют *зачем*, а не *что*. Делайте их редкими и полезными.
- Никаких новых зависимостей без предварительного обсуждения в issue.

## Строки и переводы

Каждая строка интерфейса живёт в `Core/Localization.swift` как поле структуры `Strings`. Добавление поля вынуждает каждый язык предоставить его — компилятор является гарантом полноты. Чтобы добавить язык: добавьте case в `AppLanguage` и расширение `static let` для `Strings`.

Поддерживаемые языки: **en-US**, **ru**.

## Сенсоры на новых чипах

Маппинг температур находится в `SystemMonitor.prepareSensorsIfNeeded()`:  
CPU = `Tp…`/`Te…`, GPU = `Tg…`, аккумулятор = `TB0T…TB2T`.  
Если новое поколение Apple Silicon переименует ключи, выполните:

```bash
./build/Ping4WinUtils --sensors
```

и откройте PR с дампом и скорректированными префиксами.

## Pull Requests

1. Один тип изменений на один PR, с чётким описанием поведения до и после.
2. `./build.sh` должен завершаться без предупреждений, а `--selftest` — проходить успешно.
3. Новые строки интерфейса должны появляться **на обоих** языках (en-US и ru).
4. Придерживайтесь стиля редактируемого файла.

## Отношение к оригинальному проекту

Этот форк отслеживает [vorssaint/vorssaint-utils](https://github.com/vorssaint/vorssaint-utils). При выходе новой версии upstream:

1. Смержить `upstream/main` в `main`
2. Разрешить конфликты в `Core/Localization.swift` (блок русских строк)
3. Обновить `CHANGELOG.md`, добавив секцию `[Ping4Win]` для форк-специфичных изменений
4. Создать тег и выпустить релиз
