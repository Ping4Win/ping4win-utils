## Початок роботи

```bash
git clone https://github.com/Ping4Win/ping4win-utils.git
cd ping4win-utils
./build.sh                         # збірка і збирання бандла
./build/Ping4WinUtils --selftest   # швидка перевірка (SELFTEST OK)
./build.sh --install               # встановлення в /Applications і запуск
```

**Вимоги**: macOS 14+, Apple Silicon, Xcode Command Line Tools.
Збірка — це звичайний виклик `swiftc` (див. `build.sh`), без Xcode-проєкту, без зовнішніх залежностей, відтворювана за задумом. `Package.swift` існує для того, щоб редактори з підтримкою SwiftPM могли індексувати код.

### Стабільне підписання (опційно)

За замовчуванням `build.sh` підписує ad-hoc — хеш коду змінюється при кожній збірці, і macOS повторно запитує дозволи Accessibility/Screen Recording. Виконайте

```bash
./Tools/setup-signing.sh
```

один раз, щоб створити безплатний самопідписаний ідентифікатор (`Ping4Win Utils Signing`) у відокремленому keychain. Тоді `build.sh` підписуватиме локальні збірки ним, і видані дозволи зберігатимуться між пересборками. Цей ідентифікатор — виключно локальне зручність.

Офіційні релізи підписуються **Developer ID** від Apple, нотаризуються та приклеюються автоматично через CI — завантажені релізи відкриваються без попереджень Gatekeeper.

## Структура проєкту

| Папка | Призначення |
|---|---|
| `Sources/Ping4WinUtils/App` | Життєвий цикл застосунку і елемент строки меню |
| `Sources/Ping4WinUtils/Core` | Локалізація, дозволи, ключі UserDefaults |
| `Sources/Ping4WinUtils/Services` | Уся логіка: енергія, монітор, прокрутка, switcher |
| `Sources/Ping4WinUtils/UI` | Тільки SwiftUI-представлення — без бізнес-логіки |
| `Sources/Ping4WinUtils/Support` | Діагностика `--selftest` і `--sensors` |
| `Tools` | Генератор іконок і пакування DMG |

**Конвенції:**

- **UI спостерігає за сервісами; сервіси ніколи не імпортують SwiftUI.** Зберігайте цю межу.
- Сінглтони доступні як `Type.shared` і публікують стан через Combine (`ObservableObject` — без макросів Observation).
- Коментарі пояснюють *чому*, а не *що*. Робіть їх рідкісними та корисними.
- Жодних нових залежностей без попереднього обговорення в issue.

## Рядки та переклади

Кожен рядок інтерфейсу живе у `Core/Localization.swift` як поле структури `Strings`. Додавання поля змушує кожну мову надати його — компілятор є перевіркою повноти. Щоб додати мову: додайте case до `AppLanguage` і розширення `static let` для `Strings`.

Наразі підтримувані мови: **en-US**, **ru**, **uk**.

## Сенсори на нових чипах

Мапінг температур живе у `SystemMonitor.prepareSensorsIfNeeded()`:
CPU = `Tp…`/`Te…`, GPU = `Tg…`, акумулятор = `TB0T…TB2T`.
Якщо нове покоління Apple Silicon перейменує ключі, виконайте:

```bash
./build/Ping4WinUtils --sensors
```

і відкрийте PR з дампом і скоригованими префіксами.

## Pull Requests

1. Один тип змін на один PR, з чітким описом поведінки до і після.
2. `./build.sh` має завершуватися без попереджень, а `--selftest` — проходити успішно.
3. Нові рядки інтерфейсу мають з'являтися **в усіх** мовах (en-US, ru, uk).
4. Дотримуйтесь стилю редагованого файлу.

## Відношення до оригінального проєкту

Цей форк відстежує [vorssaint/vorssaint-utils](https://github.com/vorssaint/vorssaint-utils). При виході нової версії upstream:

1. Влийте `upstream/main` у `main`
2. Розв'яжіть конфлікти в `Core/Localization.swift` (блоки російських та українських рядків)
3. Оновіть `CHANGELOG.md`, додавши секцію `[Ping4Win]` для змін, специфічних для форку
4. Створіть тег і випустіть реліз
